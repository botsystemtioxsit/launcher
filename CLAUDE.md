# CLAUDE.md

## What this is
«Ghost Shell Launcher» (раньше TIOXSIT Launcher; издатель по-прежнему TIOXSIT) — **нативное** Windows-приложение (C# / .NET 8 / WPF, один самодостаточный
`BattleLauncher.exe`). Не Electron, не веб-обёртка — владелец это прямо запретил; не
возвращать веб-технологии в сам лаунчер. Аккаунты + установка/обновление/запуск/удаление
«Тролль-Баттл» (репо `index.html`) и «БАТТЛ Админ» (репо `battle-admin-bot`) и «ВидеоЧат» (репо `videochat`, Electron-обёртка, как игра; ProductName «ВидеоЧат», видят все аккаунты игры, кроме токен-сессии). Тот же Firebase
(`zolotaya-kletka`, Spark, **без биллинга, никогда**), только REST, без SDK и без Firebase Auth.

## Layout (`Launcher/`)
- `MainWindow.xaml(.cs)` — весь интерфейс: вход, аккаунты, список приложений. Данные из базы и
  GitHub выводятся только как `Text`.
- `Services/Rtdb.cs` — REST к RTDB и Worker `/login-notify`; `Releases.cs` — версии из GitHub
  Releases (`latest.yml`); `Installer.cs` — реестр, скачивание + sha512, `/S`, запуск, удаление;
  `SelfUpdate.cs` — обновление самого лаунчера; `Catalog.cs` — список приложений и ролей;
  `AccountStore.cs` — `%APPDATA%\BattleLauncher\launcher.json`.

## Rules
- Три способа входа, как в `admin.html` (Telegram-вход не нужен): заявка по почте, токен доступа
  (`accessTokens/<token>`, сессия `Kind=token`, роль `token`, видит только админ-приложение),
  код устройства (`devicePairings/<код>`, `Paired=true`: пока нет `users/<id>/trustedDevices/<sha256(deviceId)>`
  — выходим). Секреты (токен, deviceId) только через `Secrets.Protect` (DPAPI), в логи и базу не писать.
- Планируется единый вход для будущих нативных приложений через общую сессию лаунчера — см. README
  («Единый вход»); не делать до отдельной просьбы, контракт сессии надо согласовать с владельцем.
- Вход по почте = заявка `users/<id>/loginRequests` как в игре/админке (`app: 'launcher'`; Worker для
  неизвестного `app` пишет общий текст). Секретов не хранится: только id/имя/роль. Роли в UI —
  удобство, не защита (база открыта на запись).
- Новое приложение = запись в `Catalog.cs`; в его репо нужен релиз с `latest.yml`
  (`electron-builder --publish always`). Если приложение станет нативным — научить `Installer`/`Releases` его формату.
- `FindInstalled` ищет `DisplayName == ProductName` в реестре и `<ProductName>.exe` в папке установки.
- Версию лаунчера поднимать в `Launcher.csproj` (`<Version>`) при каждом изменении, иначе релиз не обновится.
- Из этой среды .NET не поставить и Windows нет: компилирует и собирает GitHub Actions
  (смотреть логи job через GitHub MCP). Работу окна здесь проверить нельзя.

## Terminal (`Terminal/`, отдельный проект в этом же репозитории)
Нативная админ-панель (WPF, `TIOXSITTerminal.exe`). Общий код с лаунчером подключён ссылками на файлы
(`Net.cs`, `Rtdb.cs`, `AccountStore.cs`, `Catalog.cs` из `Launcher/Services`) — сессия и deviceId общие, поэтому вход
из лаунчера работает и в Терминале. Свои слои: `Terminal/Services/Db.cs` (REST + Worker `/set-status`),
`Data.cs` (чтение и разбор), `Models.cs`, `Ui.cs`; страницы — `MainWindow.Pages.cs`; `--screenshot=<папка>` — демо-снимки.
Правила: баны только через Worker (`Db.SetStatus`: аккаунт + deviceId доверенного устройства), все действия пишутся в
`logs` (`Db.Log`, без токенов и deviceId); опасные переключатели (аварийный режим, токены) — только Супердоступ, с
подтверждением; `config` целиком не читать (там секреты). Релиз Терминала — в релизе лаунчера (версия берётся из
`Launcher.csproj`); версию самого Терминала поднимать в `Terminal/Terminal.csproj`.

## Браузерная и EXE-версия (кнопки в «Приложениях»)
Всё, что лаунчер ставит сейчас, — «браузерная версия» (Electron-окна вокруг страниц): кнопка «Скачать браузерную версию».
Под ней «Скачать EXE-версию»: у приложения с `NativeExe` в `Catalog.cs` (сейчас «БАТТЛ Админ» → `TIOXSITTerminal.exe` из релиза лаунчера,
`Services/NativeInstaller.cs`: sha256 из `<файл>.sha256`, установка в `%LOCALAPPDATA%\Programs`, запись в «Установленные приложения»,
удаление через `BattleLauncher.exe --uninstall-native=<id>`) кнопка рабочая; у остальных заблокированная заглушка.
Новая нативная версия = положить `<Имя>.exe` + `.sha256` в релиз и прописать `NativeExe`/`NativeName` в `Catalog.cs`.

## Планы владельца (напоминать, когда дойдёт очередь)
- **Вкладки «Приложения» в Тролль-Баттл и Терминале (админ-панели)**: убрать то, что они делают
  сейчас, и сделать так, чтобы они вели на ссылку скачивания именно этого лаунчера
  (`https://github.com/botsystemtioxsit/launcher/releases/latest`). Владелец просил напомнить об этом
  отдельно — **не забыть напомнить при следующем заходе в эти репозитории или сразу после доделки входа**.
- **Вход по почте убрать полностью, заменить входом через Google** (нужна привязка Google-аккаунта к
  игровому, проверка ID-токена на Worker; помнить, что Firebase Auth в проекте запрещён).
- Нативные игра и админ-панель без Electron + единый вход из лаунчера (см. README).
- Подпись `.exe` (чтобы Windows не писала «неизвестный издатель») — нужен сертификат; см. обсуждение с владельцем.

## Название и издатель
Приложение — **TIOXSIT Launcher**, издатель — **TIOXSIT** (так хочет владелец; в Microsoft Store то же).
Имя файла остаётся `BattleLauncher.exe` намеренно: самообновление старых версий ищет в релизе именно его.

## Установка лаунчера
Скачанный `.exe` при первом запуске предлагает установиться в `%LOCALAPPDATA%\Programs\BattleLauncher`
(`SelfInstall`): ярлыки, запись в «Установленные приложения» (издатель `TIOXSIT`), `--uninstall`.
Самообновление меняет файл в папке установки.

## Название и дизайн (с 1.9.0)
Лаунчер — **Ghost Shell Launcher**, админ-панель-приложение — **Ghost Shell Terminal** (владелец выбрал киберпанк-стиль; везде подпись «создано нейросетью»). Меняется только то, что видит человек. Имена файлов (`BattleLauncher.exe`, `TIOXSITTerminal.exe`, `TIOXSITLauncher.apk`), ключи реестра и издатель `TIOXSIT` остаются — по ним работают самообновление и поиск установленного. Палитра: фон `#06050D`, неон-циан `#00F0FF` (Accent), маджента `#FF2A9D` (Accent2), в `App.xaml` обоих окон и в константах `MainActivity.kt`; углы острые (3–4 px), заголовки моноширинные.
